## 취약점 개요

- **취약점 요약**:  
    음식 주문 시스템에서 성인 인증이 필요한 주류를 장바구니에 추가하는 과정에서 성인 인증 없이 주류를 주문할 수 있는 취약점이 발견됨.
    
- **취약한 SW 버전**:  
    해당 취약점은 Yogiyo 안드로이드 모바일 앱에서 발생하며, BugBounty를 진행한 버전에서는 주류 상품을 장바구니에 추가할 때 성인 인증을 우회할 수 있음.
    
- **취약점 발생 환경**:  
    해당 취약점은 웹 애플리케이션에서 발생하며, Burp Suite와 같은 HTTP 프록시 도구를 이용해 JSON 요청을 수정하여 악용할 수 있습니다.
    

### 취약점 상세 설명

#### 취약점 발견 방법(점검도구 등)

- **점검 도구**: Burp Suite
    
- **점검 과정**:  
    웹사이트에서 음식을 주문하는 페이지 내에서 주류도 함께 주문할 수 있는 옵션이 있었음. 해당 시스템에서는 성인 인증이 필요하다고 명시되어 있고, 실제 장바구니에 상품을 추가할 때 `/check_adult` 로직이 실행되어 "true" 응답을 받아야만 이후 진행이 가능하도록 설계되어 있음.  
    그러나 **주류 아이템**은 가게를 로드할 때 자동으로 로드되며, 장바구니에 필요한 정보가 `vendor_product_id`, `vendor_category_id`와 함께 제공됨. 이를 통해 **성인 인증이 필요한 주류 상품을 성인 인증 없이 추가**할 수 있는 취약점이 발견됨.  
    **Burp Suite**를 이용하여 장바구니에 주류 상품을 포함하는 JSON 요청의 `Products` 필드에 주류 아이템을 추가하고, 성인 인증 없이 결제 페이지로 넘어가는 데 성공함.
    

#### 취약점 발생 원인

#### 취약점 발생 입력 데이터 설명

- **입력 데이터**:
    - JSON 형식으로 전송되는 `Products` 필드의 아이템 중 성인 인증이 필요한 주류 상품을 임의로 추가함.
    - 주류 상품의 `vendor_product_id`, `vendor_category_id` 등 장바구니 추가에 필요한 정보가 미리 로드되며 이를 수정하여 성인 인증 절차를 우회함.

#### 취약점 발생 위치 설명

- **위치**:  
    해당 취약점은 장바구니 추가 로직에서 발생하며, 주류 상품의 성인 인증 여부가 **"장바구니 추가 버튼을 클릭할 때"만** 검증되는 방식에서 발생함. 성인 인증 로직은 주류 아이템을 추가할 때만 실행되고, 이후 결제 과정에서는 추가적인 검증이 이루어지지 않음.

#### 취약점 발생 원인 설명

- **소스코드 분석**:  
    - 소스코드에서 주류 상품에 대한 성인 인증 로직이 사용자 인터페이스에서의 특정 버튼 클릭 시에만 실행되며, 장바구니나 결제 페이지로 이동할 때 추가적인 성인 인증 확인이 이루어지지 않음.  
    - **주류 상품에 대한 성인 인증이 실제로 장바구니 추가 시점에만 체크되며, 장바구니 및 결제 시점에서는 이를 반복적으로 체크하지 않음**. 이에 따라, 공격자는 Burp Suite와 같은 도구를 이용하여 성인 인증 없이 주류 상품을 장바구니에 추가할 수 있음.
    

#### 취약점 증명 / 검증

1. 취약점에 대한 상세 분석 결과 기술
    
![[FVE-2025-609b-71623-20250814090335382.png]]

대상 앱은 요식업 가게 별로 식사류를 선택하여 주문할 수 있으며, 위와 같이 주류 상품도 주문 가능 품목에 포함됨.  
명시적으로 "19세 미만의 청소년은 주문할 수 없으며, 수령 시 신분증 확인이 필요함"을 표시하고 있으며,

![[FVE-2025-609b-71623-20250814090335407.png]]

실제로 해당 상품(주류)를 추가하려고 할 때 성인인증이 호출되며, 성인임이 확인될 시 해당 상품을 장바구니에 추가하고, 그렇지 않을 경우에는 경고를 출력하며 해당 상품을 장바구니에 추가하지 않음.

![[FVE-2025-609b-71623-20250814090335440.png]]

주류는 위와 같이 다른 일반 메뉴들과 함께 보여지고 선택가능하기 때문에 다른 메뉴들은 성인인증 절차 없이 장바구니에 추가가 가능함. 

![[FVE-2025-609b-71623-20250814090335471.png]]

위와 같이 상품이 장바구니에 추가되기 위해 `/cart/v3/food/customers/900494863/restaurants/1000257/vd`  
를 호출하며 추가하고자 하는 상품을 JSON형태로 데이터 필드에 담아 전송함.  
상품들은 `vendor_product_id` 과 `vendor_cateogry_id` 정보에 의해 구분되는 것으로 보임.

![[FVE-2025-609b-71623-20250814090335497.png]]

주류 상품의 해당 필드 값을 확인하기 위해서는, 초기 가게 페이지를 로드할때 호출되는 `/v1/aggregation/get-food-shop-menus` API를 통해 전체 메뉴 중 확인할 수 있음.

![[FVE-2025-609b-71623-20250814090335542.png]]

이를 바탕으로 다른 정상 상품을 주문하면서 주류 또한 장바구니 추가 요청에 추가할 수 있으며, 성인인증 또한 요구받지 않음.

![[FVE-2025-609b-71623-20250814090335578.png]]

결제 페이지로 넘어간 이후에도 성인인증 로직은 추가 작동하지 않았으며, 카카오페이를 활용한 결제 기능까지 이상 없이 작동함.

### 취약점 악용 시나리오

- **악용 시나리오**:
    - 미성년자나 인증을 거치지 않은 사용자가 주류 상품을 결제하고 주문할 수 있음.
    - 이는 성인 인증 로직이 결제 직전 또는 장바구니를 넘어갈 때 한 번 더 확인되지 않아서 발생함.
- **영향**:
    - 미성년자나 불법적인 사용자가 주류를 구매할 수 있으며, 이는 법적인 문제를 야기할 수 있음.
    - 서비스 제공자는 성인 인증 시스템을 우회당할 수 있게 되며, 이로 인해 신뢰도 및 법적 책임이 커질 수 있음.

### 취약점 대응 방안

- **성인 인증 로직 강화**
    - 주류 상품을 장바구니에 추가할 때 **성인 인증 여부**를 재검증하는 로직을 추가합니다. 사용자가 주류 상품을 선택할 때, 서버 측에서 성인 인증이 완료되었는지 다시 한 번 확인해야 합니다.
- **결제 단계에서 추가 확인 절차 도입**
    - 결제 페이지로 이동하기 전에, 장바구니에 포함된 모든 성인 인증이 필요한 상품에 대해 **성인 인증 여부를 최종 점검**합니다. 이 단계에서 미성년자가 성인 인증 없이 주류를 구매하려고 할 경우, **경고 메시지**를 출력하고 결제를 차단합니다.
- **상품 정보 보호**
    - 주류와 같은 성인 인증이 필요한 상품은 **상품 정보 로딩** 시부터 **비즈니스 로직에 따라 필터링**하고, 사용자가 인증을 마친 경우에만 관련 정보를 로드하도록 제한합니다. 미성년자에게는 주류 상품 정보 자체가 노출되지 않도록 합니다.
- **세션 관리 개선**
    - 사용자의 인증 상태와 장바구니에 포함된 상품을 **세션 기반으로 관리**하여, 인증 상태가 변경될 경우 자동으로 **장바구니에서 해당 상품을 제거**하거나 다시 인증을 요청합니다.
- **로그 기록 및 모니터링**
    - 성인 인증 우회 시도와 같은 비정상적인 행동에 대한 **로그 기록 및 모니터링**을 강화하여, 잠재적인 공격을 사전에 탐지할 수 있는 시스템을 구축합니다.
