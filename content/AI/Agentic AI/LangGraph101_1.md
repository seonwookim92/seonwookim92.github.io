### LangGraph vs. LangChain

![[LangGraph101_1-20250817163835340.png]]

LangGraph emerged to overcome the limitations of LangChain and provides much more powerful features for creating complex and flexible AI agents. In particular, its graph structure, including cycles, and robust state management capabilities are key.

To put it simply, LangChain is like a **conveyor belt** where tasks proceed sequentially, like assembling parts in a fixed order. In contrast, LangGraph is like an **organic team project** where multiple workers communicate in real-time, perform different tasks as needed, check each other's results, and even go back to previous steps.

![[LangGraph101_1-20250817163835375.png]]

While LangGraph can be seen as a simple extension of LangChain, it is more accurate to say that it was custom-made to build complex flows that are difficult to implement in LangChain.

However, since they were developed by the same community and share the same roots, many elements of LangChain are used as is.

---

### LangGraph features

The true differentiation of LangGraph comes from the following features that make it easier to implement complex AI agents.

**1. Cyclical & Conditional Flows:** The biggest limitation of LangChain is that the workflow mostly flows in one direction. However, in LangGraph, the **graph structure** allows for moving to different nodes (task steps) based on specific conditions or **repeating (cycling)** a specific task until the desired result is obtained. This is crucial for implementing complex behaviors where the agent thinks and revises its plan (ReAct pattern).

**2. Centralized State Management:** LangGraph uses the concept of a `StateGraph` where all nodes in the graph can access and update a **single shared state object**. This state object records all information, including the user's question, the LLM's intermediate responses, and the results of tool usage. This allows any node to clearly grasp the progress so far and decide on the next action, making it easy to maintain consistency when creating complex systems where multiple agents collaborate.

**3. Human-in-the-Loop 🙋:** You can easily implement a feature that pauses the execution of the graph at a specific point and waits for human feedback. This is very useful for building more stable and reliable systems, such as having the AI agent get user confirmation before making important decisions or allowing the user to intervene and correct the path if it is going in the wrong direction.

**4. Excellent Visualization and Debugging:** LangGraph can visualize the execution flow in a graph format. This makes it much easier to debug by allowing you to see at a glance what steps a complex agent took to reach a conclusion and how it branched based on certain conditions.

### LangGraph Core Concepts

The core components that make up LangGraph are as follows.

- **State:** A data object shared across the entire graph. All nodes read and update this state, and it serves as the center of the workflow.
- **Nodes:** Units of work that represent each step in the graph. They are defined as functions or LangChain's Runnable objects. Each node takes the state as input, performs a specific task, and returns the updated state.
- **Edges:** The lines that connect nodes. They determine which node will be executed after which node.
    - **Conditional Edges:** Dynamically determine the next node to execute based on a specific condition. For example, you can set it to go to node A if the LLM's answer contains a specific keyword, and to node B otherwise.
    - **Normal Edges:** Always connect to a fixed next node.
- **Graph:** A collection of nodes and edges that defines the entire workflow. The `StateGraph` class is used to register the state, nodes, and edges, and then compile them to create an executable `CompiledGraph`.

These components come together to complete LangGraph, which acts as the brain of a complex and flexible AI agent.
